# 目標マップ ノードのカード化 — 実装仕様書（Cursor向け）

このドキュメントは「目標マップのノードをカード表示にする」作業の単一の真実（source of truth）です。`GoalNodeCard.tsx` / `goalNode.config.ts` / `goal-node.css` が確定済みのカード実装で、本書はそれをマップへ組み込むためのルールを定義します。

## 1. カードの寸法・体裁
- 幅：**230px**（許容 220–240px、まずは230で固定）
- 最小高さ：**120px**
- 角丸：12px / 内余白：上下12・左右14（左は16でバー分）
- タイトル：14px / 600 / **最大2行**・超過は省略記号（`-webkit-line-clamp:2`）
- 左端：**4pxの分野色バー**（`categoryColor` prop）
- レイアウト：上段（種別チップ＋状態）→ タイトル（伸縮）→ 下段（進捗バー＋件数）

## 2. 色の役割（重要：色でなく「要素」で意味を分ける）
| 意味 | 表現要素 | 色 |
|---|---|---|
| 分野（ユーザー設定） | **左4pxバーだけ** | ユーザー指定色 |
| 進捗 | 下部の進捗バー | 進捗色（ブランド/予約） |
| 達成済み | チェック＋取り消し線＋低彩度 | 緑（予約） |
| 期限切れ | **カード全体の枠＋右上バッジ** | 赤（予約） |
| 選択中（UI操作） | **紫の発光＋枠太め＋背景明るく** | 紫（予約） |

- **予約色（赤・緑・アンバー・紫）は分野パレットから除外**。これで「分野の赤」と「期限切れの赤」が衝突しない。
- 左バー（分野）と枠/バッジ（状態）は別要素なので、同系色でも意味は混ざらない。

## 3. 状態の出し分け（`STATUS_CONFIG` に準拠）
| status | 右上 | 枠 | その他 |
|---|---|---|---|
| `todo`（未着手） | 何も出さない | 通常 | — |
| `in_progress`（進行中） | 小さく「進行中」 | 通常 | — |
| `overdue`（期限切れ） | 赤バッジ「⏰ 期限切れ」 | **赤枠** | — |
| `done`（達成済み） | 緑チェック | 通常 | 取り消し線＋低彩度 |

- **選択中は status とは独立**。`selected` で発光のみ。`in_progress` の選択中なら「進行中」は右上に残す。

## 4. 進捗の定義（全段階共通・再帰）
- タスクは長期・中期・短期の**どの段階にも直接紐づく**。よって段階別ではなく、**全段階で同じ意味**にする。
- **進捗 ＝ その目標の配下（再帰）の「完了タスク数 ÷ 全タスク数」**。子のタスクも孫のタスクも巻き上げて数える。
- 表示：**「タスク n/m」**、バーは割合（%）。`progress.unit = "タスク"`。
- **エッジケース**：
  - 配下にタスクが0 → 進捗を**子目標の達成数（再帰）**で代用し、`progress.unit = "子目標"`（表示「子目標 n/m」）。
  - タスクも子目標も0 → 進捗バーは出さず、達成フラグ（チェック）だけで表す。
- カードは `progress.unit`（"タスク" | "子目標"）と `{done,total}` を受け取るだけ。**どちらを使うかはアダプタが判定**＝カード本体は無改修。

## 5. 既存データ → カードpropsの変換（データモデルは変えない）
カード本体は変えず、マップ側に**アダプタ**を用意して既存フィールドから導出する：
- `toGoalStatus(goal)`：`達成済み` → `done` / `期限あり && 期限 < 今日 && 未達成` → `overdue` / `配下タスクに完了が1つ以上ある（未達成）` → `in_progress` / それ以外 → `todo`
- `categoryColor`：既存の「分野/ラベル」フィールドから。無ければ中立色（例 `#7E8A99`）を既定にし、**follow-up としてメモ**（今回はブロックしない）。
- `toProgress(goal)`：§4の定義で**再帰集計**して `{done, total, unit}` を返す。
  - サブツリーの全タスクを集計：`total = 配下タスク総数`、`done = 完了タスク数`、`unit = "タスク"`。
  - タスクが0なら子目標で代用：`total = 配下子目標数`、`done = 達成済み子目標数`、`unit = "子目標"`。
  - どちらも0なら `progress` を渡さない（バー非表示）。`status` の達成フラグだけで表す。
  - 再帰集計は**メモ化推奨**（ノードが多いと毎フレーム再計算になりやすい）。木が深い場合はサーバー側で集計済み数値を返す案も検討。

## 6. エッジの接続位置（カード矩形に合わせる）
- ノードが点から矩形カードに変わるため、**エッジ端点はカードの中心ではなく矩形境界に接続**する。
- 算出：両ノード中心を結ぶ直線と、各カード矩形（幅230×高さ実測）との**交点**を端点にする（境界から2–4pxの余白を持たせると刺さって見えない）。
- react-flow / @xyflow を使っている場合は **floating edges**（getNodeIntersection / 矩形交点）パターンを採用。固定ハンドルだと位置が不自然になるため避ける。
- 選択ノードに連なるエッジのみブランド色で太く（任意・Could）。

## 7. ノード同士の重なり対策
- 自動レイアウトの**衝突半径/ノードサイズをカードのバウンディングボックス**（約230×120）に設定し、初期配置で重ならないようにする。
- **保存済み座標は正**（ユーザーが配置を保存している）。復元時は座標を尊重し、勝手に再配置しない。
- 重なりが起きた場合のみ軽く離す（declump）。保存済み座標を上書きする場合は「未保存」状態にして保存ボタンを活性化（既存仕様に合わせる）。

## 8. コンポーネントAPI（確定済み・変更不可）
```tsx
<GoalNodeCard
  goalType={goal.type}            // "long" | "mid" | "short"
  status={toGoalStatus(goal)}     // "todo" | "in_progress" | "overdue" | "done"
  title={goal.title}
  progress={{ done, total }}      // unit 省略で goalType から自動
  categoryColor={goal.categoryColor}
  selected={goal.id === selectedId}
  density="full"                  // 今回は full 固定（LODは将来）
  onClick={() => selectGoal(goal.id)}
  onContextMenu={(e) => openMenu(e, goal.id)}
/>
```
- `goal-node.css` のトークン（`--gnc-*`）はテーマ変数に差し替え可能。今回はダーク既定のままでよい。
